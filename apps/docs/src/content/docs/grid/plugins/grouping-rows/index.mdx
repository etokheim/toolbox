The Row Grouping plugin organizes your rows into collapsible hierarchical groups. Perfect for organizing data by category, department, status, or any other dimension—or even multiple dimensions for nested grouping.

## Installation

```ts
import '@toolbox-web/grid/features/grouping-rows';
```

## Custom Disclosure Controls

`disclosureRenderer` customizes only the expand/collapse control. Generated labels,
counts, aggregates and group navigation remain plugin-owned. A whole-header
`groupRowRenderer` result still takes precedence.

```tsx
import { DataGrid, type GroupingRowsConfig } from '@toolbox-web/grid-react';
import '@toolbox-web/grid-react/features/grouping-rows';

const groupingRows: GroupingRowsConfig = {
  groupOn: (row) => row.category,
  disclosureRenderer: (context) => (
    <span className="app-disclosure">
      <button
        type="button"
        aria-label={context.ariaLabel}
        aria-expanded={context.expanded}
        disabled={context.disabled}
        style={{ minWidth: 24, minHeight: 24 }}
        onClick={() => context.setExpanded(!context.expanded)}
      >
        {context.expanded ? '-' : '+'}
      </button>
    </span>
  ),
};

<DataGrid rows={items} columns={[{ field: 'name' }]} groupingRows={groupingRows} />;
```

The same typed config works in `gridConfig.features.groupingRows`. Import the
React feature entry to normalize JSX through the grid's provider-preserving portal
manager. Manually constructed core plugins remain DOM-only.

In React, setting the last `groupingRows` feature prop to `undefined` removes the
plugin even without a `gridConfig` prop. Removing an explicit `gridConfig` also
clears configuration last applied by that DataGrid; a later imperative config
replacement is not erased.

Core renderers return an `HTMLElement`, a persistent `ControlView<GroupingRowsDisclosureContext>`
(`element`, `update`, optional `dispose`), or deliberate empty `null`; React also
accepts JSX elements. Strings, `undefined` and thrown errors are diagnostic failures,
not default-control fallbacks. Same-group updates preserve persistent views and
focus; replacement, recycling, removal and disconnect dispose them and revoke stale
actions. Vue/Angular retain the DOM contract without a native template facade.

The context contains `grid`, stable `host`, existing group `key`, `value`, `depth`,
read-only `rows`, `rowCount`, `expanded`, `disabled`, `ariaLabel` and
`setExpanded(boolean)`. Identity is the composite grouping key or explicit predefined
key, not a row ID or view index. Use `disclosureLabel: (expanded) => ...` to localize
the shared native/custom label. Custom controls own their name, expanded/disabled
semantics and native click/Space/Enter activation; the grid retains navigation and
row/cell ARIA. Keep adequate button targets and avoid private `.group-toggle`
markup. Omitting the hook preserves the native control and its minimum target size.

## Accessibility

[SC 1.3.1: Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html):
grouping supplies treegrid hierarchy metadata while active. Disabling grouping or
removing the plugin restores its owned row attributes, depth styles and container
role, rather than leaving ordinary rows marked as expandable groups.

[SC 4.1.2: Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html):
native controls expose their state automatically. Custom disclosure controls must
apply their own name, role and expanded/disabled state from the context.
Fixed child sections keep hierarchy metadata without plugin-owned expansion ARIA
or disclosure controls. Whole-header renderers receive `collapsible: false` and
must omit their own expansion affordances; ordinary cell navigation is unchanged.

## Grouping Tree Children

Combine Tree and GroupingRows to group natural sibling lists beneath real parents:

```ts
groupOn: (row, { parent }) => parent === null ? null : row.category
```

The automatic [Hierarchy plugin](/grid/plugins/hierarchy/) preserves Tree structure
and supplies shared positional ARIA. Composed groups have opaque parent-scoped keys;
read them from state/events or disclosure contexts. Equal labels under different
parents expand independently, including in accordion mode. `groupOn` arrays still
describe nested paths, not multiple placements.

Aggregators receive direct sibling members. Recursive canonical totals, filtered
ancestor retention and hidden-level promotion remain consumer projection policies.
Removing grouping leaves Tree's hierarchy active; removing both releases shared
position metadata. Existing disclosure controls and standalone group keys are unchanged.

## Basic Usage

The `groupOn` callback receives each row and should return an array representing the group path. For single-level grouping, return a one-element array. For multi-level grouping, return multiple elements (e.g., `['Region', 'Department']`).

### Custom Group Row Renderer

Use `groupRowRenderer` to take full control of the group row's contents. The renderer receives a `GroupRowRenderParams` object (`key`, `value`, `depth`, `rows`, `expanded`, `toggleExpand`) and can return an `HTMLElement`, an HTML string, or `void` to keep the default rendering. The framework adapters accept their native return types (`ReactNode`, `VNode`, or a component `Type`) and bridge them automatically.

## Configuration Options

See [`GroupingRowsConfig`](./interfaces/groupingrowsconfig/) for the full list of options and their defaults.

### Default Expanded Options

The `defaultExpanded` option controls which groups are expanded on initial render:

```ts
// Expand all groups
features: { groupingRows: { defaultExpanded: true, groupOn: ... } }

// Collapse all groups (default)
features: { groupingRows: { defaultExpanded: false, groupOn: ... } }

// Expand group at index 0
features: { groupingRows: { defaultExpanded: 0, groupOn: ... } }

// Expand group with specific key
features: { groupingRows: { defaultExpanded: 'Engineering', groupOn: ... } }

// Expand multiple groups by key
features: { groupingRows: { defaultExpanded: ['Engineering', 'Sales'], groupOn: ... } }
```

With Tree, `childDefaultExpanded` optionally overrides the default beneath real
parents. Root/global groups continue using `defaultExpanded`:

```ts
features: {
  tree: { defaultExpanded: false },
  groupingRows: {
    groupOn: (row) => row.category,
    defaultExpanded: true,
    childDefaultExpanded: false,
  },
}
```

This opens global groups while real Tree parents and their child sections start
collapsed, without a post-render initializer. The override accepts `true`, `false`
or a numeric index. Omitting it preserves the shared default behaviour.
Standalone and predefined groups ignore it.

A numeric child default is resolved independently for each real parent's
first nonempty list of top-level child groups. For example, `0` opens the first
group under Alpha and the first under Beta; `1` opens each parent's second group.
Parents without groups wait until their groups first appear. If the index is out
of range at that point, no group opens and the default is not retried as the list
changes.

This initialization happens once per parent occurrence during the plugin's
lifetime. Rebuilding rows, replacing a parent with the same occurrence ID, or
collapsing and reopening Tree parents does not reopen explicitly collapsed groups.
Removing and reattaching the plugin resets initialization. Explicit expansion APIs
remain available for subsequent changes and take precedence over either default.
For example, `setGroupOn(fn, true)` still opens every visited scope, not only
root/global groups. Keep configuration identity stable for data-only React updates;
replacing the plugin configuration follows the existing detach/reinitialize lifetime.

:::note
When using `accordion: true`, prefer `defaultExpanded` with a single value
(number or string) rather than `true` or an array with multiple values.
:::

### Fixed Child Sections

With Tree, `childGroupsCollapsible: false` makes every group-path level beneath a
real parent non-collapsible. Members stay projected whenever the Tree parent is
open. Root/global groups, Tree parent expansion, standalone and predefined grouping
retain their existing behaviour. Omitted/true keeps child groups collapsible.

This overrides child defaults, pending expansion, accordion and bulk collapse;
single-group `expand`, `collapse` and `toggle` calls are no-ops for fixed sections.
Unlike an always-expanded default, user actions cannot collapse them. Their public
model reports `expanded: true` and `collapsible: false`, with unchanged keys,
counts and category order. Rebuilding or reparenting data needs no reopening repair.

The plugin omits expansion ARIA and disclosure controls for fixed sections.
Whole-header `groupRowRenderer` receives `collapsible: false`; use it to omit your
own expansion controls. Ordinary cell navigation remains available.

For sticky sections, use the existing [StickyRows](/grid/plugins/sticky-rows/) push
mode and identify fixed groups through the current public model:

```ts
const sticky = new StickyRowsPlugin({
  mode: 'push',
  isSticky: (_row, index) => {
    const item = grouping.getFlattenedRows()[index];
    return item?.kind === 'group' && item.collapsible === false;
  },
});
```

Here `grouping` is the attached `GroupingRowsPlugin` instance. Native header cells
and `.cell`-based whole-header output receive current processed indexes from
GroupingRows, including after recycling. Do not stamp `data-row` in consumer code.
Custom cells must be direct row children for StickyRows' existing capture lookup.
Nested grids' header and body cells are not stamped with the outer group's index.
For content-measured variable-height rows, the grid measures owned rendered rows
on forced layout refreshes, including small datasets that bypass virtualization.
Sticky push boundaries therefore use those measured offsets rather than repeating
the first row's estimated height. Explicit configured and plugin-provided heights
remain authoritative; application code should not repair the private position cache.
StickyRows push mode is not ancestor stacking or automatic parent-boundary expiry;
rich headers that have never rendered may not be synthesized.

### Category Order

Use `groupOrder` for a semantic category order independent of column sorting:

```ts
groupingRows: {
  groupOn: (row) => row.category,
  groupOrder: ({ parent }) => parent === null ? undefined : ['Primary', 'Secondary'],
}
```

The callback receives the same `{ parent, depth }` context as `groupOn`. It is
resolved once per natural sibling-list model build; the ranking is reused across
nested group-path levels within that list. Returning `undefined` at the root keeps
global Group by ordering unchanged.

Listed normalized category segments form a fixed prefix, even with descending
column sorting. Unlisted categories follow normal value/direction ordering.
Duplicates use their first position, and absent categories create no empty groups.
Values, labels, scoped keys, counts and data-row sorting are unchanged. Omitted,
`undefined` or empty rankings preserve normal ordering. Predefined groups retain
their supplied order.

`setGroupOrder(callback)` updates an attached plugin without resetting expansion
or selection; `setGroupOrder(undefined)` restores normal ordering. The same callback
reference is a no-op. React's `groupingRows` prop and `gridConfig.features.groupingRows`
both apply callback-only replacement and clearing through this setter. Other config
changes retain their existing initialization lifecycle.

### Animation Options

The `animation` option controls how newly revealed rows appear, including nested
group headers and fixed child sections. Reveal tracking uses stable row occurrence
IDs and parent-scoped group keys, not view indexes. Collapsing an earlier group
does not animate surviving rows that shift position. Supply `getRowId` when row
objects may be replaced while retaining the same logical occurrence.

```ts
// Slide animation (default)
features: { groupingRows: { animation: 'slide', ... } }

// Fade animation
features: { groupingRows: { animation: 'fade', ... } }

// No animation
features: { groupingRows: { animation: false, ... } }
```

:::note
Animation respects the grid-level `animation.mode` setting.
:::

### Accordion Mode

In accordion mode, only one group can be expanded at a time. Expanding a group automatically collapses all sibling groups at the same depth level.



```ts
features: {
  groupingRows: {
    groupOn: (row) => row.department,
    accordion: true, // Only one group open at a time
  },
},
```

### Aggregators

<ShowSource file="demos/grouping-rows/GroupingRowsWithAggregatorsDemo.astro">
  <GroupingRowsWithAggregatorsDemo />
</ShowSource>

Display aggregate values (sum, avg, count, min, max, first, last) in group headers. Works in both full-width and per-column rendering modes.



```ts
features: {
  groupingRows: {
    groupOn: (row) => row.department,
    aggregators: {
      salary: 'sum',    // Sum of salaries in each group
      bonus: 'avg',     // Average bonus
      id: 'count',      // Count of rows
    },
  },
},
```

**Built-in aggregators:**
- `sum` - Sum of numeric values
- `avg` - Average of numeric values
- `count` - Number of rows
- `min` - Minimum value
- `max` - Maximum value
- `first` - First row's value
- `last` - Last row's value

You can also provide a custom aggregator function:

```ts
aggregators: {
  salary: (rows, field) => {
    const total = rows.reduce((sum, r) => sum + r[field], 0);
    return `$${total.toLocaleString()}`;
  },
}
```

## Programmatic API

See [`GroupingRowsPlugin`](./classes/groupingrowsplugin/) for the full list of methods.

```ts
const plugin = grid.getPluginByName('groupingRows');

plugin.expand('Engineering');
plugin.collapse('Engineering');
plugin.toggle('Engineering');
plugin.expandAll();
plugin.collapseAll();
plugin.isExpanded('Engineering');    // boolean
plugin.getExpandedGroups();          // string[]
plugin.setGroupOn((row) => [row.region, row.department]);
// Optionally pass an initial expansion that resolves against the *new* groups
// (issue #335). Avoids the stale-snapshot race when chaining setGroupOn → expandAll.
plugin.setGroupOn((row) => row.counterparty, true);
plugin.setGroupOn((row) => row.region, ['EMEA', 'AMER']);
plugin.refreshGroups();
```

## Server-Side Data

> **Requires:** `ServerSidePlugin` — [see Server-Side Plugin](/grid/plugins/server-side/)

For server-side scenarios where group structure is fetched from the server and rows are loaded on demand, use `ServerSidePlugin` alongside Row Grouping. ServerSide returns group definitions as root data; when the user expands a group, the plugin fetches group rows via `getChildRows()`.

<Tabs syncKey="framework">
  <TabItem label="TypeScript">
```ts
import '@toolbox-web/grid/features/grouping-rows';
import '@toolbox-web/grid/features/server-side';
import { queryGrid } from '@toolbox-web/grid';

const grid = queryGrid('tbw-grid');
grid.gridConfig = {
  columns: [
    { field: 'name', header: 'Employee' },
    { field: 'department', header: 'Department' },
    { field: 'salary', header: 'Salary', type: 'currency' },
  ],
  features: {
    serverSide: {
      pageSize: 50,
      dataSource: {
        async getRows(params) {
          // Return group definitions as root-level nodes
          const res = await fetch(`/api/groups?start=${params.startNode}&end=${params.endNode}`);
          const data = await res.json();
          return { rows: data.groups, totalNodeCount: data.total };
        },
        async getChildRows(params) {
          // Return rows for an expanded group
          const { groupKey } = params.context;
          const res = await fetch(`/api/groups/${groupKey}/rows`);
          return { rows: await res.json() };
        },
      },
    },
    groupingRows: true,
  },
};
```

**Data flow:**
1. ServerSide fetches block → broadcasts `datasource:data`
2. GroupingRowsPlugin claims data as pre-defined groups
3. On group expand → fires `datasource:fetch-children` with `{ source: 'grouping-rows', groupKey }`
4. ServerSide calls `getChildRows()` → broadcasts `datasource:children`
5. GroupingRowsPlugin receives rows and renders them under the group

:::note
Child rows are fetched as a single batch — no pagination. If a group has many rows, limit the response server-side.
:::

### Standalone Mode (Without ServerSide)

If `ServerSidePlugin` is not loaded, use the imperative API to provide groups and rows directly:

```ts
import '@toolbox-web/grid/features/grouping-rows';
import { queryGrid } from '@toolbox-web/grid';

const grid = await queryGrid('tbw-grid', true);
grid.gridConfig = {
  columns: [
    { field: 'name', header: 'Employee' },
    { field: 'department', header: 'Department' },
    { field: 'salary', header: 'Salary', type: 'currency' },
  ],
  features: {
    groupingRows: true,
  },
};

const grouping = grid.getPluginByName('groupingRows');

// Lazy-load rows when a group is expanded
grid.on('group-expand', async ({ groupKey }) => {
  grouping.setGroupLoading(groupKey, true);
  const rows = await fetchGroupRows(groupKey);
  grouping.setGroupRows(groupKey, rows); // also clears loading state
});

// Load groups asynchronously
const groups = await fetch('/api/groups').then(r => r.json());
grouping.setGroups(groups);
```

:::note
`setGroupRows()` automatically clears the loading indicator — no need to call `setGroupLoading(key, false)` afterwards.
:::

| Method | Description |
| --- | --- |
| `setGroups(groups)` | Replace groups with an external structure |
| `getGroups()` | Get the current group definitions |
| `setGroupRows(key, rows)` | Populate rows for an expanded group |
| `setGroupLoading(key, loading)` | Toggle loading indicator for a group |
| `clearGroupRows(key?)` | Clear cached rows (specific group or all) |

const groups: GroupDefinition[] = [

## Plugin Compatibility

:::caution[Incompatible Plugins]
The Row Grouping plugin **cannot** be used with the following plugins:

- **[Tree](/grid/plugins/tree/)** — Both plugins transform the entire row model. Tree flattens nested hierarchies while Row Grouping groups flat rows with synthetic headers. Use one approach per grid.
- **[Pivot](/grid/plugins/pivot/)** — Pivot creates its own aggregated row and column structure. Row grouping cannot be applied on top of pivot-generated rows.
:::

A development-mode warning is shown if incompatible plugins are loaded together.
